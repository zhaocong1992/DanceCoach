## 五、功能四：投屏（CastManager — 首页右上角图标入口）

### 5.1 定位

投屏是**辅助功能**，不占据首页 4 大功能卡片之一。入口为首页右上角小图标（类似 YouTube/Bilibili 的投屏按钮），点击后弹出设备选择对话框。

### 5.2 技术方案

使用 Android 原生 **MediaRouter API** + **Presentation API**：

| 组件 | 作用 |
|------|------|
| `MediaRouter` | 发现并连接智能电视/无线显示设备 |
| `Presentation` | 在第二屏幕（电视）上渲染内容 |
| `DisplayManager` | 监听显示设备连接/断开 |

**不引入 Google Cast SDK**，避免额外依赖和 Google Play Services 依赖。使用 Android 原生 API 即可支持 Miracast/Wi-Fi Display 协议的智能电视。

### 5.3 投屏内容

投屏时在电视上显示一个 **镜像画面**，包含：
- 老师视频播放区（ExoPlayer 输出到 Presentation）
- 摄像头预览区（摄像头帧同步到 Presentation）
- 分数 + 进度 + 提示文字
- 手势选择面板

手机端可作为遥控器，仅显示精简控制界面。

### 5.4 交互流程

```
首页右上角投屏图标
  → 点击 → 弹出设备选择对话框（非独立页面）
  → 扫描附近的显示设备
  → 选择设备 → 建立连接
  → 图标变高亮 + 显示"已连接到 [设备名]"
  → 进入教学后，内容同步显示在电视上
  → 再次点击图标 → 断开连接
```

### 5.5 实现要点

- `CastManager` 单例管理 MediaRouter 生命周期
- `HomeActivity` 右上角图标点击触发 `CastManager.showDeviceChooser()`
- `TeachingActivity` 在投屏连接后创建 `Presentation`，将关键 UI 同步渲染
- 摄像头帧通过 Surface 共享到 Presentation
- ExoPlayer 使用 `setVideoSurfaceView()` 输出到 Presentation 的 SurfaceView
- 投屏状态通过 LiveData 通知各 Activity

### 5.6 权限变更

AndroidManifest 新增：
```xml
<!-- 投屏不需要额外权限，MediaRouter 是系统 API -->
<!-- 但需要注册 MediaRouteChooser 和 MediaRouteButton -->
```

build.gradle 新增：
```groovy
implementation 'androidx.mediarouter:mediarouter:1.2.5'
```

## 六、功能五：教学市场（MarketActivity — 首页第 3 张卡片）

### 6.1 功能定位

社区功能：用户可以浏览、上传、下载、分享舞蹈教学视频。打造一个舞蹈爱好者社区，让用户不仅能用自己本地视频练习，还能发现其他用户分享的优质舞蹈视频。

### 6.2 功能列表

| 功能 | 说明 |
|------|------|
| 浏览市场 | 展示社区分享的舞蹈视频列表（卡片网格），含缩略图、名称、分享者、难度、下载次数 |
| 搜索 | 按名称/标签/舞种搜索 |
| 筛选 | 按难度（简单/中等/困难）、按舞种分类、按热门/最新排序 |
| 视频详情 | 查看视频详情：预览片段、段数、时长、分享者信息、下载次数、评分 |
| 下载到舞蹈库 | 下载视频到本地舞蹈库，可直接开始练习 |
| 上传分享 | 从本地舞蹈库选择视频上传分享到市场，填写名称、舞种、难度、描述 |
| 评分 | 下载练习后可对视频打分（1-5 星），影响排行 |
| 收藏 | 收藏喜欢的视频，方便日后下载 |

### 6.3 界面设计

- **横屏**布局
- 顶部：搜索栏 + 筛选标签（全部/简单/中等/困难）+ 排序下拉 + 上传按钮
- 中间：视频卡片网格（2-3 列），每张卡片显示缩略图 + 名称 + 分享者 + 难度标签 + 下载次数
- 底部：分页加载更多

### 6.4 数据层

教学市场需要后端服务支持。初期方案分两种路径：

#### 方案 A：纯本地 P2P（MVP，无需后端）
- 视频元数据通过局域网广播发现（类似 Bluetooth File Transfer）
- 或通过 WebDAV/FTP 共享目录
- 优点：无需服务器，零运维成本
- 缺点：体验差，需要用户在同一局域网

#### 方案 B：云服务（正式版，推荐）
- 搭建轻量后端（Firebase Storage / 腾讯云 COS + 云函数）
- 视频文件存储在对象存储，元数据存数据库
- 用户上传/下载通过 API
- 优点：体验好，社区规模可扩展
- 缺点：需要服务器成本和账号体系

> **建议**：v4.0 先做方案 A 的框架和 UI，后端对接留接口。市场页面先用本地数据展示功能流程，后端接入在后续版本迭代。

## 十、风险与注意事项

| 风险 | 说明 | 应对 |
|------|------|------|
| ExoPlayer 双屏输出 | ExoPlayer 2.15.1 可能需要切换 Surface | 使用 `setVideoSurfaceView()` 动态切换 |
| MediaRouter 兼容性 | 部分电视不支持 Miracast | 投屏失败时给出友好提示，不影响正常使用 |
| compileSdk 30 限制 | MediaRouter 1.2.5 需要 SDK 30 | 版本兼容，minSdk 21 可用 |
| 左侧栏移除影响 | TeachingActivity 布局重构 | 保留逻辑不变，仅改布局文件 |
| SharedPreferences 线程安全 | 设置变更时教学正在运行 | 使用 `apply()` 异步写入，读取时加默认值 |
| 图标资源 | 需要绘制 5 个 Vector Drawable | 使用 Material Design 图标参考 |
| 教学市场后端依赖 | 社区功能需要后端服务 | v4.0 先做 UI + 本地 mock 数据，后端接口预留 |

## 十二、设置功能补充说明

除用户提到的相似度阈值外，设置页面还可包含以下功能：

| 设置项 | 理由 |
|--------|------|
| 手势确认时间 | 当前硬编码 1.5s，用户可能觉得太快/太慢 |
| 原子动作最短时长 | 当前硬编码 2s，不同舞蹈类型需求不同 |
| 老师播放速度 | 慢动作回放对初学者很有用 |
| 摄像头选择 | 后置摄像头画质更好，但前置更方便自拍 |
| 镜像翻转默认值 | 不同场景需求不同 |
| 骨架显示开关 | 性能较差的设备可关闭以提升帧率 |
| 缓存管理 | 长期使用缓存会占用大量空间 |
| 投屏设备入口 | 在设置中也可进入投屏 |
| 版本/版权 | 合规需求 |
