# 舞蹈市场 — 功能设计文档

> 文档状态：设计稿 v1（2026-08-16）· 方向已与用户确认（BaaS 免费档起步 + 积分激励）· 待评审
> 配套背景：见 `PROJECT_OVERVIEW.md`（整体架构）。本文件只讲"舞蹈市场"这一块。

---

## 1. 这个功能要解决什么问题

现在 APP 是装在每台手机上的"单机软件"，用户自己跳的舞蹈视频、自己整理的动作库文件，都只存在各自手机里，互相看不见。

"舞蹈市场"就是建一个**所有用户都能访问的公共仓库**，让大家能：
- **上传**自己跳的舞 / 自制的动作库；
- **浏览**别人分享的内容；
- **下载**回来播放、或导入到本机舞蹈库里跟着练。

一句话：让"内容"在用户之间流动起来，APP 从"单机工具"变成"有社区的工具"。

## 2. 核心能力（第一版先做这些）

### 2.1 上传
用户在 APP 里选一段本地视频（mp4）或一个动作库文件，填标题、选分类（如民族舞/街舞/健身操），点上传。
- 文件通过 BaaS（后端即服务，见第 3 节）存到云端"网盘"。
- 同时写一条"目录记录"到数据库（标题、作者、分类、时长、封面、下载地址、下载次数、上传时间）。

### 2.2 浏览 / 发现
市场页拉取"目录记录"列表，用卡片展示（封面图 + 标题 + 作者 + 下载数）。
- 支持**分类筛选**、**搜索**（按标题/作者/标签）。

### 2.3 下载与导入
点开某条 → 调下载地址把文件取回：
- 视频：本地播放；
- 动作库文件：一键**导入本机舞蹈库**，形成"下载即内容生产"的闭环（你练的就是别人编的）。

### 2.4 热门排序（按下载量 + 播放量 / 热度）
每条记录带两个计数：**下载次数**（downloadCount）和**播放次数**（playCount，即别的用户在市场里把这条视频播了多少次）。
- 用户每**有效下载**一次 → downloadCount +1。
- 用户每在市场对这条视频**播放**一次 → playCount +1（上报云端）。
- **热门榜**：按"热度分"从大到小排，热度分把两个信号合起来，例如：
  `热度分 = 播放次数×1 + 下载次数×3`（下载是更强意图，权重更高；比例可后续调）。
  下载多、播放多的自然排最前——正是你要的效果。
- **最新榜**：按上传时间排（可切换）。
- 更聪明的"火"：热度分还可加"近 7 天活动×权重"，让近期涨起来的更靠前（趋势榜）。点赞数以后接入也并入。

## 3. 技术实现原理（白话）

把云端想成"一个网盘 + 一本目录本（数据库）"：

```
用户点上传
   │
   ├─► 视频/库文件 ──► BaaS 文件存储（云端硬盘）──► 拿到下载地址
   │
   └─► 标题/作者/分类/下载地址/下载次数=0 ──► BaaS 数据库（那本目录本）

别人打开市场页
   │
   └─► 拉目录本（按"下载次数"从多到少排）──► 显示卡片列表

用户点下载
   │
   ├─► 按地址从文件存储取回文件
   └─► 数据库里这条的"下载次数 +1"
```

- **BaaS（Backend as a Service，后端即服务）**：别人把"服务器+数据库+文件存储+登录"打包成现成服务，你只调接口，不用自己装维护。推荐国产 **微信云开发 / LeanCloud / Bmob**（国内访问稳、中文文档、有免费额度）；Firebase 更成熟但国内偶尔不稳。
- **数据库**：就是一张大表（类似 Excel），记"有哪些内容、各自在哪"。排序、筛选、搜索都是这张表上的操作，BaaS 原生支持。
- **接口/API**：APP 和云端对话的"固定话术"，比如"给我下载最多的前 20 条"。
- **动作分析仍在本机跑**（用现有 ML Kit），服务器只存文件、记目录、传文件，不碰打分——最省最快。

### 3.1 登录与用户身份（积分系统的硬前提）

你说得对：**要积分，就必须能锁定"这是哪个用户"**。否则"被下载 +2 给谁""同一内容重复下载怎么去重""币余额存在哪"全都无从谈起。所以登录不是可选项，而是积分系统的前提。

- **鉴权（登录）**：BaaS 自带"用户认证"，免费、不用你自己做账号系统。每个登录用户会拿到一个**稳定且唯一的 userId**（用户身份证号），所有积分变动都记在这个 userId 名下。
- **积分余额存在云端（不在手机上）**：舞币余额是一张"用户表"里的字段，由服务器说了算。手机本地的数字只是显示用，改不了真值——这样才防作弊（用户不能自己改本地文件就变出币）。
- **两种登录档位**（按阶段选）：
  - **匿名登录**（早期、零摩擦）：APP 首次打开，BaaS 自动给这台手机发一个 userId，用户无感、不用填任何东西。缺点：卸载重装或换手机，这个身份就丢了，里面的币也没了。
  - **真实登录**（微信 / 手机号，推荐在积分上线前接通）：用户用微信或手机号登录，身份**跨设备持久**。好处：换手机币还在、能做"防刷"（同一真人不能开小号刷）、充值退款也能对账。
  - 务实路线：先匿名登录跑通流程；**第一次涉及"赚/花/买币"前，引导用户绑定微信/手机号**，把匿名身份升级成真实身份，避免币随卸载丢失引发投诉。

### 3.2 云端要记的两张表（数据模型）

把"目录本"拆成两张大表（都是 BaaS 数据库里的表，类似 Excel 的两个 sheet）：

**① 内容表（dances）**——每条分享一条记录
| 字段 | 含义 |
|---|---|
| id | 内容唯一编号 |
| title / authorId / authorName | 标题、上传者 userId、昵称 |
| category / tags | 分类、标签（用于筛选搜索） |
| coverUrl / fileUrl | 封面图地址、文件下载地址 |
| downloadCount | 下载次数（热门排序用） |
| playCount | 播放次数（市场内被播放次数，热门排序用） |
| hotScore | 热度分（趋势榜用，= 播放次数×1 + 下载次数×3，比例可调） |
| createdAt | 上传时间（最新榜用） |

**② 用户表（users）**——每个用户一条记录（"维护用户有效信息"就靠它）
| 字段 | 含义 |
|---|---|
| userId | 登录拿到的唯一身份证号 |
| nickname / avatar | 昵称、头像 |
| points | **舞币余额**（服务器权威值） |
| signinStreak | 连续签到天数（每日签到用） |
| lastSignIn / createdAt | 上次签到、注册时间 |

> 上传时：往 dances 写一条 + 给 users 里自己那行 points +20。
> 下载时：dances 的 downloadCount +1，下载者 users 的 points -5，上传者 users 的 points +2（平台留 3）。全部是云端事务，保证不错不乱。

### 3.3 APP 端要做的登录 / 注册功能（前端工作量，必须列入方案）

BaaS 只负责"验证身份、发 userId"这件后台事；**用户看得到的登录/注册界面和流程，都得 APP 自己写**。具体要做的：

1. **登录/注册入口**：在"我的"页或首页给一个明显的登录按钮（未登录时显示）。
2. **登录方式界面**：
   - **微信一键登录**：一个按钮，点一下跳微信授权，回来就拿到 userId。（需先注册"微信开放平台"账号并把 APP 登记上去，有一次性 300 元认证费 + 应用审核，约几天。）
   - **手机号 + 验证码**：输入框填手机号 → 点"获取验证码" → 填码登录。验证码由 BaaS 发短信（LeanCloud 等自带，按条计费或有免费额度）。
   - 备注：**注册和登录是一回事**——用 BaaS 不需要你自建"用户名密码表"，用户第一次用微信/手机号登录，系统自动建好那条 users 记录；以后再登就是老用户。无密码、无"注册成功"单独页。
3. **匿名用户的无感升级**：早期用匿名登录（APP 自动发 userId，用户无感）。当触发"赚/花/买币"时，弹窗引导绑定微信或手机号，把匿名身份升级成真实身份（否则币会随卸载丢失）。
4. **登录态保持（会话）**：登录后 APP 把 userId/登录凭证存在本地（BaaS 的 SDK 通常自动管好"令牌"，重启 APP 不用重新登）。要处理令牌过期时静默刷新。
5. **退出登录**：设置里给"退出"按钮，清掉本地登录态。
6. **个人资料编辑**：昵称、头像的修改界面，写回 users 表。
7. **账户中心**：展示舞币余额、连续签到、充值入口（充值界面本身也归 APP 做，见 4.4）。
8. **隐私与合规**：手机号、微信头像昵称都是个人信息，需配套《隐私政策》和用户同意勾选；微信登录需通过平台审核。

> 工作量判断：登录/注册是"舞蹈市场"里**最大的一块前端新增**，但 BaaS 把最难的身份校验、短信、令牌都托管了，APP 主要做的是按钮、输入框、流程串联和资料页。建议把它和 users 表一起，作为市场模块的第一批开发内容。

## 4. 让更多人愿意分享：积分（虚拟币）经济

光有仓库不够，要让人"主动上传"。思路：用一套**虚拟积分**把"上传"和"下载"连成循环，平台在中间赚差价，用户用真钱买积分——这就是你说的机制，可行，下面把它设计清楚。

### 4.1 积分叫什么 / 是什么
- 暂定叫"**舞币**"（虚拟激励道具，不是真钱、不能提现，见 4.5 合规）。
- 作用：APP 内的"钱"，用来下载内容、买增值服务；也能靠贡献赚到。
- **门槛**：浏览市场可以开放（匿名也能看），但**赚币、花币、买币都必须已登录**（见 3.1）。未登录用户点下载/上传时，APP 弹窗引导先登录或匿名绑定，否则无法计入积分。

### 4.2 怎么赚（激励上传与活跃）
| 行为 | 得币 | 说明 |
|---|---|---|
| 新用户注册 | +50 | 启动资金，够先下几份 |
| 每日签到 | +5~10 | 留人，养成打开习惯 |
| 上传 1 份（审核通过） | +20 | 质量高的可加权 |
| 被他人**有效下载** 1 次 | +2 | 上传者收益，来自下载者付的币 |
| 被点赞 / 收藏 | 少量 + | 社交激励 |
| 等级 / 活跃奖励 | 阶段性 + | 见第 5 节 |

### 4.3 怎么花
| 行为 | 付币 |
|---|---|
| 下载 1 份 | -5（有效下载才扣；同内容重复下载折扣或免扣） |
| 购买增值功能（如云备份、专属滤镜，可选） | 按档 |

### 4.4 平台差价与变现（你的收入来源）
关键在你说的"中间赚差异"：
- 下载者付 **5 舞币**，平台结算给上传者 **2 舞币**，差额 **3 舞币**归平台。
- 这 3 舞币对冲服务器/流量成本，并有正现金流（利润）。
- 用户舞币不够时，用**真钱充值**买舞币（如 6 元=60 舞币），这是平台变现入口。
- 结果：上传者越被下，越赚币→越愿意上传好内容；下载者为继续下→充值。三方循环，平台抽成。

> 比例只是示例，上线前可按"让优质上传者划算、下载者不肉疼、平台有盈余"调。

### 4.5 防刷 + 合规（重要，先说清）
- **防刷**：同一 userId 对同一内容只计一次有效下载；上传设质量/审核门槛，避免垃圾刷分；舞币产出设每日上限；真实登录（微信/手机号）可进一步限制"同真人开小号刷"。
- **合规红线**：舞币**只能 APP 内消费，不可提现、不可私下交易、不可反向换人民币**。明确定义为"虚拟激励道具"，避免触碰"虚拟货币 / 二清"金融监管风险。充值档要公示比例、支持退款规则，符合应用商店（微信/各安卓市场）审核要求。

## 5. 可以继续扩展的能力（想象空间，促进分享）

按"让人更愿意分享"的目标，往后可以加：

1. **创作者主页 + 关注**：每个上传者有自己的主页（作品集、粉丝数），别人可关注。被关注本身就有成就感。
2. **点赞 / 收藏 / 评论**：社交反馈是最直接的分享动力。
3. **等级、徽章、头衔**：如"铜牌→金牌舞蹈老师""连续签到 30 天"。荣誉感驱动持续贡献。
4. **每周主题挑战赛 + 排行榜 + 奖励**：比如"本周最火民族舞"，前几名奖舞币或实物。制造事件和话题。
5. **标签 / 分类 / 搜索 / 推荐**：让你本地舞蹈库"缺哪类"就推荐哪类，下载更准、上传更有方向。
6. **下载即导入闭环**：下载的动作库直接进本机舞蹈库（已在 2.3），分享者等于在"供给教学素材"。
7. **合拍 / 跟练排行**：用户用同一支舞录自己的版本，系统按相似度排"谁跳得最像"，玩法化促进上传与对比。
8. **优质内容加权曝光**：被下载/点赞多的，在热门榜自然靠前（呼应 2.4），形成"好内容→更多曝光→更多下载"正循环。

## 6. 成本与阶段建议

- **阶段一（现在就能做，0 成本）**：BaaS 免费档 + 上传/浏览/下载/热门排序。验证有没有人用。
- **阶段二（有小流量后）**：上积分经济 + 签到 + 基础社交（点赞收藏）。免费档仍够，靠充值小规模变现试水。
- **阶段三（规模起来、触免费线后）**：升 BaaS 付费档（按需/包月）；再加挑战赛、创作者主页、合拍等重功能。
- **始终 0 服务器运维**：BaaS 托管底层，你只写 APP 侧调用。

## 7. 术语小词典

- **后端 / 服务器**：24 小时开机的远程电脑，替所有用户统一管文件和数据。
- **BaaS（后端即服务）**：把"服务器+数据库+存储+登录"打包成现成服务，你只调接口、不自己运维。
- **数据库**：一张大表（像 Excel），记"有哪些内容、各自在哪"；排序/筛选/搜索都在它上面做。
- **文件存储**：云端硬盘空间，专门放大文件（视频、库文件）。
- **接口 / API**：APP 和云端对话的固定话术，如"给我下载最多的前 20 条"。
- **排序查询（ORDER BY … DESC）**：按某列从大到小排；DESC=从多到少。
- **分页加载**：内容多时分批取（每次 20 条，下滑再取下一页），保证流畅。
- **有效下载**：同一用户对同一内容只计一次，防刷分。
- **合规 / 二清**：虚拟币若可提现或私下交易会触金融监管；定义为"APP 内虚拟道具、不可提现"即可规避。
