# 舞蹈市场丰富化方案（A 视觉与发现 / B 社交互动 / C 激励体系）

> 背景：当前市场仅实现首期闭环骨架（上传从库 / 下载进库 / 内联预览 / 热门·最新切换），封面是纯色块 + 首字，无分类、无搜索、无互动。设计稿 `dance_market_design.md` 规划的二期（社交、积分）/ 三期（挑战赛、排行榜）尚未落地。
> 本次目标：按勾选的 **A 视觉与发现 + B 社交互动 + C 激励体系** 三个方向做丰富。先对齐设计与关键决策，确认后分三期开发，每期构建安装到真机验证。

---

## 一、后端现状（已具备的地基）

云端 `dances` 集合 / 云函数 `danceApi` 当前已支持：

- `list(sort=hot|latest)`、`get`、`upload`（带 `title/category/coverUrl/description/authorId`）
- `reportPlay`、`reportDownload`（已维护 `playCount/downloadCount/hotScore`）
- `getUploadCredential` / `getFileUrl` 直传直取、`delete`

**缺失**：分类筛选参数、搜索、点赞/评论字段、`users` 表。→ A 组大部分前端即可接上，B/C 需补少量后端。

---

## 二、A 组 · 视觉与发现（低成本，后端基本就绪）

| 功能 | 做法 | 后端改动 |
|---|---|---|
| **真实视频封面** | 上传时从库视频抽首帧 → 压缩 JPG → 复用 `getUploadCredential` 走 PUT 上云，存 `coverFileId`/`coverUrl`；卡片显示真实缩略图 | `upload`/`getFileUrl` 支持封面；`list` 返回 `coverUrl` |
| **分类筛选** | 前端加分类条（民族舞/街舞/健身操/古典/少儿/其他），点选过滤 | `list` 增加 `category` 内存过滤 |
| **搜索** | 前端搜索框，按标题/作者匹配 | `list` 增加 `keyword` 内存过滤 |
| **难度徽章** | 库视频 `difficulty` 上传时带回 `dances.difficulty`；卡片显示「简单/中等/难」标签，可一并筛选 | `upload` 增加 `difficulty` 字段 |

> 这一组是"最直观出效果"的，且基础字段后端已埋好，工作量主要在 APP 端 UI + 封面抽帧。

## 四、C 组 · 激励体系（大工程，硬前提多）

设计稿机制（比例可调）：下载者付 **5 舞币**、上传者得 **2**、平台留 **3**；上传 **+20**、每日签到 **+5~10**、新用户 **+50**。

**硬前提（设计稿 3.1 已明确）**：积分必须锁定"是哪个用户"，否则币给谁、去重、余额都存在哪都无从谈起 → **必须登录**。当前首期是匿名登录（设备 `deviceId`），币不跨设备、易随卸载丢失、无法防刷。

| 模块 | 做法 | 后端改动 |
|---|---|---|
| **登录** | 微信一键登录 / 手机号+验证码（设计稿 3.3）。需注册开放平台、配短信，有一次性成本与审核 | 引入 `users` 表、登录态 |
| **账户中心** | 余额、连续签到、充值入口 | 新增 `signin`/`getBalance`/`recharge` 动作 |
| **币变动** | 上传/被下载的币增减走云端事务 | 新增 `changePoints`；`upload`/`reportDownload` 内联动 |

> 这是原"二期/三期"内容，工作量最大、且涉及合规（虚拟币不可提现、充值需隐私政策与商店审核）。

## 五、⚠️ 需要你拍板的关键决策

1. **实施顺序**：建议 **A → B → C**（先最快见效），你认可吗？还是想先攻 C，或只做 A+B？
2. **C 组做到什么程度**：
   - (a) 暂不做，等 A/B 完成再议（推荐，先把体验做厚）；
   - (b) **匿名 + 本机舞币**体验版（不跨设备、易作弊，但能先跑通"赚/花"玩法，零登录成本）；
   - (c) **真实登录 + 完整积分含充值**（大工程 + 合规 + 审核）。
3. **分类方式**：固定下拉枚举（民族舞/街舞/健身操/古典/少儿/其他）还是自由标签？

## 七、确认结论（2026-08-24）

三项决策点已确认（均取推荐项）：

1. **推进顺序**：**A → B → C**。先做视觉与发现，再做社交互动，最后积分大工程。
2. **C 组程度**：**暂不做 C**。激励体系（舞币/签到/充值/登录）留待 A/B 完成后再议。
3. **分类方式**：**固定枚举**（民族舞/街舞/健身操/古典/少儿/其他）。

### 第一期（当前进行中）：A 组 · 视觉与发现

实现清单（按依赖与见效速度排序）：

- **A-1 分类筛选**：`list` 增加 `category` 内存过滤；前端加分类条；上传页带固定枚举分类。
- **A-2 搜索**：`list` 增加 `keyword`（匹配 `title`/`authorName`）；前端加搜索框。
- **A-3 难度徽章**：库视频 `difficulty` 上传时带回 `dances.difficulty`；卡片显示「简单/中等/难」并可筛选。
- **A-4 真实视频封面**：上传时抽首帧→压缩 JPG→复用 `getUploadCredential` 上云，存 `coverFileId`/`coverUrl`；卡片显示真实缩略图（替代纯色块）。

后端 `danceApi` 需新增/增强：`list` 的 `category`/`keyword` 过滤、`upload` 的 `difficulty`/`coverFileId` 字段。前端 `MarketActivity`/`MarketUploadActivity`/`item_market_dance` 布局相应改造。
