# 我的舞蹈库 - 需求文档

> 版本: v1.0 | 日期: 2026-08-16

## 1. 模块概述

「我的舞蹈库」是 DanceCoach APP 的第二大功能模块，允许用户批量导入舞蹈视频、管理视频库、并对每个视频进行离线动作预审（姿态检测 + 动作分段），为「跳舞教学」模块提供经过质量验证的舞蹈素材。

### 1.1 核心价值

- **批量导入**：一次性导入多个视频，自动提取元数据和缩略图
- **预审核机制**：导入后自动进行骨架检测和动作分段，不合格视频提前预警
- **统一管理**：所有舞蹈视频集中管理，查看历史练习分数和分析状态

### 1.2 与现有模块的关系

- 复用 `VideoCacheManager` 管理视频库索引和缓存
- 复用 `PoseExtractor` 进行离线骨架检测（SINGLE_IMAGE_MODE）
- 复用 `Segmenter` 进行动作分段
- 分析完成后，视频可直接跳转到 `TeachingActivity` 开始练习

## 2. 功能需求

### 2.1 视频批量导入

| 需求项   | 描述                                                          |
| ----- | ----------------------------------------------------------- |
| 多选导入  | 调用系统文件选择器（GET_CONTENT, type=video/*），支持多选                   |
| 元数据提取 | 自动提取视频时长、文件大小、修改时间、缩略图                                      |
| 去重校验  | 基于 MD5(uri+size+mtime) 去重，已存在的视频不重复导入                       |
| 导入反馈  | 显示导入进度（逐个处理），完成后显示新增数量                                      |
| 权限处理  | Android 13+ 使用 READ_MEDIA_VIDEO，低版本使用 READ_EXTERNAL_STORAGE |

### 2.2 舞蹈库管理

| 需求项  | 描述                                |
| ---- | --------------------------------- |
| 列表展示 | 横向滚动网格（2行×N列），每项显示缩略图、名称、时长、状态、分数 |
| 状态标识 | 三种状态：未分析（灰色）、分析中（蓝色脉动）、已分析（绿色/红色） |
| 排序   | 默认按最近导入排序；可选按最高分、名称排序             |
| 删除   | 长按进入多选模式，可批量删除（含缓存清理）             |
| 重命名  | 单击项进入详情面板，可修改显示名称                 |
| 空状态  | 无视频时显示引导插画 + "导入你的第一个舞蹈视频"        |

### 2.3 动作预审

这是本模块的核心功能。导入的视频经过自动骨架检测，评估视频是否适合用于教学。

#### 2.3.1 分析流程

1. 使用 `PoseExtractor.detectTeacherFrame()` 对视频按时取样（每 200ms 一帧）
2. 对每帧运行 ML Kit Pose Detection（SINGLE_IMAGE_MODE）
3. 使用 `Segmenter` 对骨架序列进行动作分段
4. 计算动作质量评分

#### 2.3.2 质量评估指标

| 指标    | 说明                 | 合格阈值  |
| ----- | ------------------ | ----- |
| 检测率   | 成功检测到骨架的帧数 / 总取样帧数 | ≥ 70% |
| 平均置信度 | 所有检测到骨架的帧的平均综合置信度  | ≥ 0.5 |
| 有效帧数  | 检测到完整躯干（双肩+双髋）的帧数  | ≥ 15帧 |
| 分段数   | Segmenter 拆解出的动作段数 | ≥ 3段  |

- 四项指标全部达标 → 质量合格（绿色标记）
- 任一指标不达标 → 质量警告（橙色标记），仍可使用但给出提示
- 检测率 < 30% → 质量不合格（红色标记），建议重新导入

#### 2.3.3 分析队列

- 支持后台排队分析多个视频
- 分析进度实时更新（百分比 + 当前阶段提示）
- 分析过程中可在列表中看到进度条
- 支持取消正在进行的分析

### 2.4 视频详情面板

单击视频项弹出底部操作面板（BottomSheet 风格）：

| 操作   | 说明                           |
| ---- | ---------------------------- |
| 开始练习 | 跳转 TeachingActivity，传入视频 URI |
| 重新分析 | 清除缓存，重新执行动作预审                |
| 查看骨架 | 全屏查看视频 + 骨架叠加预览              |
| 重命名  | 修改 displayName               |
| 删除   | 确认后删除视频及关联缓存                 |

## 3. 数据模型变更

### 3.1 VideoLibraryEntry 扩展

```kotlin
data class VideoLibraryEntry(
    // ... 现有字段保持不变 ...
    
    // 新增字段
    val analysisStatus: AnalysisStatus = AnalysisStatus.NONE,
    val analysisProgress: Int = 0,           // 0-100
    val skeletonQuality: Float = -1f,        // 0-100, -1=未分析
    val detectionRate: Float = 0f,           // 检测率 0-1
    val avgConfidence: Float = 0f,           // 平均置信度 0-1
    val validFrameCount: Int = 0,            // 有效帧数
    val analysisMessage: String? = null      // 分析提示信息
)

enum class AnalysisStatus {
    NONE,       // 未分析
    QUEUED,     // 排队中
    ANALYZING,  // 分析中
    ANALYZED,   // 已分析（合格）
    WARNING,    // 已分析（有警告）
    FAILED      // 分析失败/不合格
}
```

### 3.2 向后兼容

- 新字段在 JSON 中使用 `optXxx` 读取，旧数据自动获得默认值
- `analyzed: Boolean` 字段保留，映射为 `analysisStatus != NONE`

## 6. 交互流程

### 6.1 完整使用流程

```
首页 → 我的舞蹈库 → [导入视频] → 系统多选 → 导入中...
                                      ↓
                              自动加入分析队列
                                      ↓
                         列表中显示分析进度 ⏳
                                      ↓
                    分析完成 → 点击查看预审核结果
                                      ↓
                    质量合格 → [开始练习] → 跳转教学页
                    质量警告 → 提示但允许练习
                    质量不合格 → 建议重新导入
```

### 6.2 与教学页的集成

- 从舞蹈库跳转教学页时，传入 `VideoLibraryEntry.id`
- TeachingActivity 检查 `analysisStatus`，若已分析则直接加载缓存分段
- 若未分析，提示用户先进行预审核（可选跳过）

## 7. 非功能需求

| 项  | 要求                            |
| -- | ----------------------------- |
| 性能 | 单个视频分析耗时 < 视频时长的 1/3          |
| 内存 | 分析时按需加载帧，不缓存全部 bitmap         |
| 存储 | 缩略图压缩至 < 50KB，骨架序列缓存 < 1MB/视频 |
| 横屏 | 所有页面强制横屏，与现有 APP 一致           |
| 主题 | 深色主题（#0B0E14 背景），与首页一致        |
| 返回 | 支持系统返回键返回上一页                  |
